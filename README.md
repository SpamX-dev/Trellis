# Trellis

Trellis организует инженерные знания в YAML-документы, помогает агентам их заполнять и позволяет человеку принимать изменения. Граф строится из документов и известных полей ссылок, когда он нужен для анализа.

## Основа

- Принятые YAML-документы — источник знаний. Рендер, граф и поисковые индексы являются производными.
- Каждый проект хранится в отдельном локальном Git-репозитории. Для чтения, поиска и графа Knowledge предоставляет файловые снимки точных ревизий; рабочие копии агентов изолированы от принятого состояния.
- Первый сценарий Framework описывает продукт и требования к нему: Product, US, FR, NFR, BO и BP.
- Агент читает каталоги и файлы обычными средствами. Документ по строковому идентификатору можно найти через grep или ripgrep.
- Изменение одного или нескольких документов предлагается целиком. Проверки и решение человека относятся к конкретному содержимому предложения.
- Графовая БД, отдельный индекс идентификаторов и MCP для обычного чтения файлов не обязательны.
- Правила записываются непосредственно в контрактах и описаниях границ компонентов.

## Целевой рабочий цикл

1. Человек выбирает домен и агента, сообщает задачу через клиент; Tasks фиксирует задачу.
2. Tasks выбирает опубликованный пакет агента в Registry и назначает работу Runtime.
3. Агент читает свой текст с инструкциями и правилами работы, а также нужные документы; при необходимости задаёт человеку вопрос через Tasks.
4. Агент готовит итоговые артефакты и отдельное рабочее предложение YAML-документов.
5. Knowledge сохраняет итоговые артефакты и проверяет структуру документов, идентификаторы и ссылки в предложении.
6. Клиент показывает состояние задачи, документы, изменения, замечания и открытые вопросы.
7. Человек применяет или отклоняет точную версию предложения.
8. Tasks назначает явно настроенные реакции на принятое изменение; Runtime исполняет назначенную работу.

Структурная проверка подтверждает форму и связи. Смысловая проверка возвращает выводы с основаниями и может завершиться неопределённостью. Наличие ссылки или успешно заполненного документа не доказывает соответствие продукта ограничению.

## Проекты и доступ

Knowledge управляет созданием и архивацией проектов, их названием, описанием, владельцем и доступом. Идентификатор проекта не зависит от имени или пути репозитория. Архивация запрещает публикацию изменений, сохраняя историю и чтение согласно выданным правам.

Keycloak — выбранный провайдер человеческих пользователей, свободной регистрации, входа и групп. Его локальное развёртывание описывается внутри Knowledge и использует Docker с PostgreSQL. Глобальная роль `admin` назначается явно через Keycloak, а не первому зарегистрировавшемуся пользователю. Она позволяет управлять настройками и жизненным циклом проектов, но сама по себе не предоставляет доступа к содержимому. Проектный `owner` управляет доступом; `owner` и допущенные `user` работают с документами и принимают изменения. Членство в группе Keycloak само по себе не выдаёт проектных прав.

Агент имеет название, собственный токен Knowledge и явный список доступных проектов. Управление агентами и их токенами выполняется через UI; проектные назначения проверяет Knowledge. Агент может публиковать ветки предложений, но не принимать изменения или менять настройки проекта. Вход людей через Keycloak и токены агентов имеют отдельные механизмы проверки.

Внешние обработчики получают подписанные webhook об опубликованных изменениях выбранных Git-веток. Изменение ветки предложения не является принятием знаний: событие `documents.accepted` появляется только после проверок, решения человека и согласованной публикации Knowledge.

## Проверка репозитория

Требуется Node.js 22 или новее.

```sh
npm ci
npm run check
npm test
npm run build
```

Проверка компилирует TypeScript Framework и [пример четырёх документов](trellis-framework/examples/product/README.md), а также проверяет локальные Markdown-ссылки. Тест проверяет разбор внешних значений, импорт точек входа и комментарии в декларациях. Сборка охватывает Framework, API и Web. Проверка полного YAML-снимка добавляется следующим шагом плана.

В репозитории также есть первый контур сервера Knowledge, локальный Keycloak и web UI. Он управляет проектами и правами и читает зафиксированные Git-снимки. Tasks пока описан как граница; работающий сервис задач и интерфейс задач, Git HTTPS, принятие изменений, webhook, MCP, запуск агентов и расширение VS Code остаются отдельными этапами.
