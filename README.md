# Trellis

Проект предоставляет анализ репозиториев и их связанности через семантический граф заний

## Ограничения

Не анализирует код, не строит LSP дерево

## Что реально содержит

База знаний сожержит ддокументы которые построены агентами и соеденены семетической связью.
Т.о. вся БЗ связана в единый граф и для добавления документов в БЗ нужно описать семантику связи с другими документами.

## Как это работает

### Роли

- Оператор
- Агент
- Навык
- База зананий
- Документ

### Последовательность

- Оператор хочет изменить документ (требования к продукту, требовани к архитектуре или иной документ)
- Агент смотрит на семантику документа - проводит опрос
- Агент берет необходимый навык и формирует изменения в граф знаний
- БЗ принимает изменения и строит черноик измнений
- Рендерит документ
- Человек смотрит на изменения в графе и документах
- Применяет изменения

## Использование

### Проблематика

Обычно изменение не затрагивает один репозиторий и принять решение довольно сложно.

### Решение

Когда требование сфоромировано, оно разложится в граф и установит влияние, можно провести трассировку и выяснить затрагиваемые цепочки.
Тогда будет сразу видно что нужно менять и где.

## Полная цепочка ценности

```text
Requirement ──refines──> Architecture change (module)
                              │
                              └──decomposes──> Task
                                                 │
                                    ┌────────────┼────────────┐
                                    │            │            │
                              Coding agent   Commit      Review agent
                                    │            │            │
                                    └──produces──┴──links─────┘
                                                 │
                                          Task + Code = verified link
```
