# Граница Trellis Framework

## Назначение

Framework определяет декларативные контракты Trellis: формат YAML-документов, состав доменов, определения агентов и навыков, рендер, проверку и принятие изменений. Один агент отвечает за одну ограниченную задачу; связь нескольких задач не входит в его определение.

## Внутренние границы

- [Contracts](contracts/module.md) — общие соглашения, JSON Schema конфигурации и документов процесса.
- [Domains](domains/module.md) — предметные схемы и связанные с ними агенты и представления.
- [Examples](examples/module.md) — конкретные учебные документы и сценарии применения контрактов.
- [Конфигурация доменов](domains.yaml) — точка сборки доменной модели.

## Зависимости и ограничения

Framework не исполняет агентов, не хранит рабочую базу знаний и не применяет изменения. Knowledge проверяет документы и предложения; Tasks координирует гейты задач; Runtime исполняет агентов; интерфейс предоставляет клиент.

Форма данных описывается JSON Schema в YAML. Семантика полей и смысловые критерии находятся рядом со схемой. Описания границ объясняют ответственность каталогов. Примеры не вводят новых общих типов.

Авторское определение пакета связывает `AGENTS.md`, YAML-навыки, схемы входа и выхода и детерминированные гейты в YAML. Сборка включает целевую схему и все её зависимости из одного снимка Framework. Проверяющий компонент использует эти схемы как данные для валидации, а Runtime предоставляет агенту их текст из того же пакета. Пакет не выдаёт проектных прав и не заменяет проверки Knowledge.
