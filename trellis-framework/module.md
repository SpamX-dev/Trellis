# Граница Trellis Framework

Framework определяет общие типы и проверки задач агента, конкретную модель продуктовых документов и сборку комплекта для внешнего исполнителя. Декларации типов с комментариями служат контрактом и передаются исполнителю как текст; авторские инструкции о процедуре и размещении остаются отдельным текстом и не выводятся из типов полей. Библиотека предоставляет отдельные точки входа для общего кода, [product](src/product/module.md) и [node](src/node/module.md). Реализации агентов хранятся в [Runtime](../trellis-runtime/agents/module.md) и в сборку пакета не входят. [Примеры](examples/module.md) используют точки входа библиотеки для конкретного сценария.

Продуктовые документы хранятся в Git как YAML. Framework получает вход задачи и содержимое точной ревизии от вызывающего компонента; он проверяет структуру документов и условия завершения, но не получает проектные права, не управляет Git-репозиторием и не принимает изменения. Knowledge владеет доступом, снимками и принятием; Tasks — жизненным циклом задач; Runtime — исполнением агента; Registry — распространением версий пакетов.

Корневой импорт не выполняет файловых операций. Файловое чтение и сборка находятся в `node`. Продуктовые правила не создают общего каталога доменов или постоянного графа.
