# Сборка домена

## Точка входа

[domains.yaml](../domains.yaml) перечисляет домены. Каждый домен содержит `schema`, `agent` и `render`. Пути разрешаются относительно файла конфигурации и остаются внутри Framework.

Определение схемы — стандартная JSON Schema 2020-12 в YAML-синтаксисе. Используются `$defs` и `$ref`, а не собственный язык полей. Идентификаторы схем с префиксом `https://trellis.local/framework/` служат локальными именами; загрузка по сети не требуется и проверкой не выполняется.

Определения типов документа находятся в `$defs` схемы домена. Корень содержит `oneOf` со ссылками на них; каждый тип имеет постоянное значение `type`. Одно имя типа принадлежит одному домену.

## Ответственность и исполнение

Агент содержит `domain`, общий `prompt` и `skills`. Навык содержит имя, авторскую процедуру и ссылку `schema` на формат результата; при необходимости — пути к примерам. Ссылки разрешаются относительно определения агента.

Runtime собирает контекст из инструкции, навыка, выбранной схемы, её смысловых критериев и примеров. Источники знаний, порядок уточнений и работа с неопределённостью задаются авторской процедурой. Они не генерируются из имени или типа поля.

Владелец домена отвечает за предложения документов своего домена. Это не означает единственный процесс-писатель и не запрещает читать соседние домены. Фактические разрешения определяет среда исполнения, а не поле, переданное самим агентом.

## Аннотации

| Аннотация | Содержание | Потребители |
| --- | --- | --- |
| `x-trellis-ref` | `targets` и имя направленной `relation`. Ставится на строку-ссылку, в массиве — на `items`. | Проверка ссылок, граф и инструкции автора. |
| `x-trellis-checks` | Критерии с устойчивыми `id`, `severity` и `prompt`. | Автор и AI-проверяющий. |

Форма аннотаций проверяется [схемой](annotations.schema.yaml). Они регистрируются в Ajv явно; неизвестные ключевые слова схем остаются ошибкой. JSON Schema не проверяет существование документа по ссылке и не исполняет смысловые критерии.

AI-проверка возвращает `check_id`, исход `pass | fail | unknown`, локацию и основание. Для находки указывается фрагмент документа или конкретный источник; при `unknown` — недостающие данные. Результат не считается доказательством только потому, что его сформировал отдельный агент.

## Представление

Рендер содержит названия типов и упорядоченные поля с подписями. Он показывает данные выбранного документа; ссылки разрешаются в том же снимке базы. Вложенные объекты и массивы отображаются структурно.

Поле, не перечисленное в рендере, выводится после известных полей под собственным именем. Ни пропуск в конфигурации, ни неизвестный тип представления не должны скрывать изменения. Исходный YAML-diff всегда доступен.

Рендер предназначен для чтения. Редактирование произвольного текста рендера и обратное преобразование в YAML не входят в контракт.

## Версии

Локальные ссылки не содержат отдельных версий: вся конфигурация, схемы, агенты, примеры и рендер фиксируются одним снимком Framework. Запуск и предложение сохраняют `framework_revision`. При использовании Git это точный commit; в учебном примере используется явно условное имя снимка.

Во время одного запуска зависимости не переключаются на новую ревизию. Изменение схем требует проверки совместимости и, при необходимости, явного преобразования документов. YAML-хранение не отменяет миграции смысла и формы данных.

Registry может распространять собранные агенты и навыки с происхождением из этого снимка. Он не нужен для запуска локальных определений.
