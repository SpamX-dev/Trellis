# Trellis Framework

Локальный npm workspace-пакет `@trellis/framework` для описания продуктовых документов, агента сбора требований и проверок его результата. [План](plan.md) задаёт последовательность реализации. [Граница библиотеки](module.md) отделяет её от Knowledge, Tasks, Runtime и Registry.

Декларации типов с русскими комментариями — это и схема документов, и контракт для внешнего агента: исполнителю передаётся текст деклараций, а не отдельно сгенерированные инструкции. Авторские инструкции о процедуре и размещении пишутся отдельно и не выводятся из типов полей.

## Сборка

Из корня репозитория:

```sh
npm ci
npm run check
npm test
npm run build
```

Пакет собирается в `trellis-framework/dist` как ESM с декларациями TypeScript. Доступны точки входа `@trellis/framework`, `@trellis/framework/product` и `@trellis/framework/node`. Через `product` экспортируются [четыре типа документов](src/product/model.ts) и `parseProductDocument`; корневой импорт предоставляет типы задачи, `parseTaskInput` и `parseTaskResult`. Документы [учебного примера](examples/product/README.md) хранятся как YAML; форму типов проверяет `npm run check`.

Функции разбора принимают `unknown` и возвращают `{ ok: true, value }` либо `{ ok: false, issues }`. Каждая ошибка содержит код, путь от `$` и сообщение. Они не изменяют входные объекты и не исправляют строки или списки.

## Текущие ограничения

Разбор проверяет форму отдельного документа, входа или отчёта. Он не читает YAML-файлы и не проверяет связи между документами одного Git-снимка; это следующий шаг [плана](plan.md). Агент, Git-гейты и сборка его комплекта также выполняются отдельными шагами. `check` проверяет типы библиотеки, [проверки типов](test/model-types.ts) и локальные Markdown-ссылки; `test` проверяет разбор внешних данных и декларации. Старые JSON Schema и примеры не используются.
