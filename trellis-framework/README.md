# Trellis Framework

Локальный npm workspace-пакет `@trellis/framework` для описания продуктовых документов, агента сбора требований и проверок его результата. [План](plan.md) задаёт последовательность реализации. [Граница библиотеки](module.md) отделяет её от Knowledge, Tasks, Runtime и Registry.

Декларации типов с русскими комментариями — это и схема документов, и контракт для внешнего агента: исполнителю передаётся текст деклараций, а не отдельно сгенерированные инструкции. Авторские инструкции о процедуре и размещении пишутся отдельно и не выводятся из типов полей.

## Сборка

Из корня репозитория:

```sh
npm ci
npm run check
npm test
npm run build
```

Пакет собирается в `trellis-framework/dist` как ESM с декларациями TypeScript. Доступны точки входа `@trellis/framework`, `@trellis/framework/product` и `@trellis/framework/node`. Через `product` экспортируются [шесть типов документов](src/product/model.ts) — Product, US, FR, NFR, BO и BP — а также `parseProductDocument` и `checkProductSnapshot`; через `node` — строгий разбор `parseStrictYaml`. Корневой импорт предоставляет типы задачи, `parseTaskInput` и `parseTaskResult`. Документы [учебного примера](examples/product/README.md) хранятся как YAML; форму типов проверяет `npm run check`.

Реализации агентов хранятся в [trellis-runtime/agents](../trellis-runtime/agents/module.md) обычным Markdown, без TS-описаний. Задача агента узкая, поэтому [agent.md](../trellis-runtime/agents/product/agent.md) включает и инструкцию, и правила работы с документами, и ручную копию деклараций типов модели; источник истины — [model.ts](src/product/model.ts).

Функции разбора принимают `unknown` и возвращают `{ ok: true, value }` либо `{ ok: false, issues }`. Каждая ошибка содержит код, путь от `$` и сообщение. Они не изменяют входные объекты и не исправляют строки или списки.

Проверка снимка принимает содержимое файлов продуктовой области с путями `documents/product/<type>/<id>.yaml` и проверяет строгий YAML, форму каждого документа, размещение путей, уникальность идентификаторов, единственный Product и ссылки между документами. Порядок файлов на результат не влияет.

## Текущие ограничения

Разбор покрывает отдельный документ, вход, отчёт и целостность переданного снимка. Агент сбора требований описан Markdown в [Runtime](../trellis-runtime/agents/product/agent.md); Git-гейты завершения, сборка файлового комплекта агента и сквозной Git-пример выполняются следующими шагами [плана](plan.md). `check` проверяет типы библиотеки, [проверки типов](test/model-types.ts) и локальные Markdown-ссылки; `test` проверяет разбор внешних данных, YAML, снимок и декларации. Старые JSON Schema и примеры не используются.
