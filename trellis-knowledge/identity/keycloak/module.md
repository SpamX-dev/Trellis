# Граница Keycloak

## Назначение

Keycloak является выбранным внешним провайдером человеческих пользователей, входа, групп и глобальных ролей Trellis. Эта граница включает интеграцию с [Identity](../module.md) по OIDC и локальное развёртывание Keycloak в Docker с PostgreSQL как постоянным хранилищем.

## Ответственность

- Управление человеческими учётными записями, паролями и входом по логину и паролю.
- Свободная регистрация пользователей в realm `trellis`. Регистрация не предоставляет доступ к существующим проектам.
- Управление группами и членством через штатный административный интерфейс Keycloak.
- Явное назначение глобальной роли администратора Trellis: роль `trellis-admin` соответствует `admin` в Knowledge; группа `trellis-admins` предоставляет эту роль своим участникам.
- Выдача подтверждённой личности и атрибутов через OIDC. Связь с внутренней идентичностью Knowledge строится по `issuer + sub`.
- Граница конфигурации локального Docker-развёртывания, подключения PostgreSQL и воспроизводимого восстановления realm `trellis` из Git при запуске контейнера.

## Конфигурация локального окружения

`compose.yaml` задаёт отдельное Docker Compose окружение `trellis-identity`: Keycloak и PostgreSQL с именованным томом `postgres-data`. Интерфейс публикуется только на `127.0.0.1`, по умолчанию на порту `8080`; режим `start-dev` предназначен для локальной разработки.

`.env.example` описывает параметры запуска; локальный `.env` хранит пароли администратора Keycloak и PostgreSQL и исключён из Git. Эти пароли применяются при первой инициализации соответствующего хранилища. Правка этих значений не заменяет пароли существующих учётных записей. Пароль `111` тестовых пользователей хранится непосредственно в `trellis-realm.json` и восстанавливается при каждом импорте без требования сменить его при входе.

`trellis-realm.json` в рабочей копии Git является источником конфигурации локального realm `trellis`: настройки регистрации, роли, группы, тестовые пользователи, их имена и членство. Идентификаторы realm, прикладных ролей, групп и пользователей закреплены в файле; идентификаторы пользователей сохраняют `sub` при повторном импорте. Группа `trellis-admins` предоставляет роль `trellis-admin` и не является группой по умолчанию. Остальные прикладные роли не назначаются автоматически по совпадению имени группы или пользователя.

Все тестовые пользователи имеют общий email `loca@local`. В локальном realm разрешены повторяющиеся email (`duplicateEmailsAllowed: true`), а вход по email отключён (`loginWithEmailAllowed: false`): для входа используется уникальный логин пользователя. Email заполнен заранее, чтобы вход не требовал дополнения профиля.

Перед каждым запуском сервера контейнер выполняет `kc.sh import --file /opt/keycloak/data/import/trellis-realm.json --override true`. Импорт полностью заменяет realm `trellis`; при ошибке сервер не запускается. Запуск сервера происходит только после успешного импорта, в этом окружении разрешён один экземпляр Keycloak. Realm `master`, его администратор и пароль не входят в импорт.

Изменения через UI/API, новые регистрации, пароли и другие данные realm `trellis`, отсутствующие в JSON, сбрасываются при следующем запуске контейнера. Конфигурационные изменения нужно переносить в JSON; секреты — в локальный `.env`. Активные сеансы и ключи подписи не сохраняются при замене realm, поэтому после перезапуска пользователи входят заново. Этот режим предназначен для воспроизводимого локального окружения, а не хранения действующих пользовательских данных.

На новой машине скопируйте `.env.example` в `.env` и задайте пароли PostgreSQL и администратора. Запуск из этой директории: `docker compose up -d --wait`. Для применения правок JSON к работающему серверу: `docker compose restart keycloak`; обычный `up` без пересоздания уже работающего контейнера не запускает повторный импорт. После правок `.env` или Compose используйте `docker compose up -d --wait --force-recreate keycloak`. Автоматического `git pull` нет: импортируется файл из текущей рабочей копии.

Остановка: `docker compose down`. Том PostgreSQL сохраняется, но при следующем запуске realm `trellis` всё равно заменяется. `docker compose down -v` удаляет все данные этого окружения, включая `master`. Изменение порта меняет OIDC issuer, поэтому клиенты и сопоставления идентичностей должны учитывать новый адрес.

## Зависимости

[Identity](../module.md) принимает подтверждённую личность и глобальные роли; [Projects](../../projects/module.md) независимо определяет проектные полномочия. Docker обеспечивает локальное окружение, PostgreSQL хранит состояние Keycloak.

## Ограничения

Первый зарегистрировавшийся человек автоматически администратором не становится. Назначение `trellis-admin` выполняется явно администратором Keycloak. Администратор Keycloak и администратор Trellis имеют разные полномочия; управление Keycloak само по себе не является проектной ролью Trellis.

Keycloak не хранит владельцев проектов, проектные роли `owner` и `user` или списки разрешённых агентам проектов. Членство в группах не предоставляет права на проекты без отдельного назначения в Knowledge.

Для агентов используется выбранная модель собственных токенов Knowledge. Управление этими токенами не входит в интеграцию Keycloak. Секреты развёртывания и пароли действующих пользователей не размещаются в Git-документах проектов. Явное исключение локального окружения — общий пароль `111` тестовых пользователей в конфигурации realm.
