# Граница Keycloak

## Назначение

Keycloak является выбранным внешним провайдером человеческих пользователей, входа, групп и глобальных ролей Trellis. Эта граница включает интеграцию с [Identity](../module.md) по OIDC и локальное развёртывание Keycloak в Docker с PostgreSQL как постоянным хранилищем.

## Ответственность

- Управление человеческими учётными записями, паролями и входом по логину и паролю.
- Свободная регистрация пользователей в realm `trellis`. Регистрация не предоставляет доступ к существующим проектам.
- Управление группами и членством через штатный административный интерфейс Keycloak.
- Явное назначение глобальной роли администратора Trellis: роль `trellis-admin` соответствует `admin` в Knowledge; группа `trellis-admins` предоставляет эту роль своим участникам.
- Выдача подтверждённой личности и атрибутов через OIDC. Связь с внутренней идентичностью Knowledge строится по `issuer + sub`.
- Публичный клиент `trellis-web` использует Authorization Code + PKCE, добавляет аудиторию `trellis-api` в access token для API Knowledge и разрешает отдельный адрес возврата после выхода для локального и Vite окружений.
- Граница конфигурации локального Docker-развёртывания, подключения PostgreSQL и создания realm `trellis` из Git при первом запуске.

## Конфигурация локального окружения

`compose.yaml` задаёт отдельное Docker Compose окружение `trellis-identity`: Keycloak и PostgreSQL с именованным томом `postgres-data`. Интерфейс публикуется только на `127.0.0.1`, по умолчанию на порту `8080`; режим `start-dev` предназначен для локальной разработки.

`.env.example` описывает параметры запуска; локальный `.env` хранит пароли администратора Keycloak и PostgreSQL и исключён из Git. Эти пароли применяются при первой инициализации соответствующего хранилища. Правка этих значений не заменяет пароли существующих учётных записей. Пароль `111` тестовых пользователей задан в `trellis-realm.json` для первоначального импорта без требования сменить его при входе.

`trellis-realm.json` в рабочей копии Git задаёт начальную конфигурацию локального realm `trellis`: настройки регистрации, роли, группы, тестовые пользователи, их имена и членство. Идентификаторы realm, прикладных ролей, групп и пользователей закреплены в файле. Группа `trellis-admins` предоставляет роль `trellis-admin` и не является группой по умолчанию. Остальные прикладные роли не назначаются автоматически по совпадению имени группы или пользователя.

Все тестовые пользователи имеют общий email `loca@local`. В локальном realm разрешены повторяющиеся email (`duplicateEmailsAllowed: true`), а вход по email отключён (`loginWithEmailAllowed: false`): для входа используется уникальный логин пользователя. Email заполнен заранее, чтобы вход не требовал дополнения профиля.

Keycloak запускается с `start-dev --import-realm`. Он импортирует `trellis-realm.json` только если realm `trellis` ещё отсутствует. При последующих запусках содержимое PostgreSQL сохраняется, включая пользователей, пароли, роли и ключи. Realm `master`, его администратор и пароль не входят в импорт.

После первого запуска изменение JSON не меняет существующий realm. Изменения через UI/API, новые регистрации и пароли сохраняются в PostgreSQL. Для переноса действующих данных между ПК нужны снимки базы Keycloak, базы Knowledge и Git-репозиториев; перенос одного JSON их не заменяет.

На новой машине без снимка скопируйте `.env.example` в `.env` и задайте пароли PostgreSQL и администратора. Запуск из этой директории: `docker compose up -d --wait`. Для применения правок JSON к уже существующему realm нужен отдельный контролируемый перенос конфигурации через Keycloak; перезапуск контейнера не заменяет действующие данные. После правок `.env` или Compose используйте `docker compose up -d --wait --force-recreate keycloak`. Автоматического `git pull` нет: при первом импорте берётся файл из текущей рабочей копии.

Остановка: `docker compose down`. Том PostgreSQL и realm `trellis` сохраняются. `docker compose down -v` удаляет все данные этого окружения, включая `master`. Изменение порта меняет OIDC issuer, поэтому клиенты и сопоставления идентичностей должны учитывать новый адрес.

## Зависимости

[Identity](../module.md) принимает подтверждённую личность и глобальные роли; [Projects](../../projects/module.md) независимо определяет проектные полномочия. Docker обеспечивает локальное окружение, PostgreSQL хранит состояние Keycloak.

## Ограничения

Первый зарегистрировавшийся человек автоматически администратором не становится. Назначение `trellis-admin` выполняется явно администратором Keycloak. Администратор Keycloak и администратор Trellis имеют разные полномочия; управление Keycloak само по себе не является проектной ролью Trellis.

Keycloak не хранит владельцев проектов, проектные роли `owner` и `user` или списки разрешённых агентам проектов. Членство в группах не предоставляет права на проекты без отдельного назначения в Knowledge.

Для агентов используется выбранная модель собственных токенов Knowledge. Управление этими токенами не входит в интеграцию Keycloak. Секреты развёртывания и пароли действующих пользователей не размещаются в Git-документах проектов. Явное исключение локального окружения — общий пароль `111` тестовых пользователей в конфигурации realm.
