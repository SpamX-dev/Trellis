# Контракт первого этапа Projects и Repositories

## Состояние и хранение

Knowledge хранит метаданные в собственной PostgreSQL, отдельно от базы Keycloak. Идентичность человека задаётся парой `issuer + sub`; каталог назначаемых людей пополняется после их первого входа. Проект имеет UUID, название, описание, одного владельца-человека и состояние `provisioning`, `failed`, `active` или `archived`. Обычный каталог показывает только `active` и `archived`; `provisioning` и `failed` доступны глобальному администратору для повторения создания.

Хранилище Git — отдельный bare-репозиторий в закрытом серверном томе с именем по UUID проекта. Создание идемпотентно: запись `provisioning` предшествует созданию репозитория, а `active` устанавливается только после проверки bare-репозитория и `refs/heads/main`. Первый `main` указывает на коммит с пустым деревом. Повтор использует тот же UUID и не перезаписывает существующие коммиты. Отказ Git оставляет проект в `failed`; администратор может повторить создание.

Участник `owner` определяется полем владельца проекта. Дополнительные люди имеют роль `user`. Агент получает доступ только через отдельное назначение проекта. `admin` управляет метаданными и агентскими учётными записями, но без роли в проекте не читает содержимое. `owner` управляет назначениями, в том числе на архивном проекте; архивирование запрещает публикацию, но сохраняет чтение по текущим правам.

## HTTP API

Все пути ниже имеют префикс `/api`. Вход человека — OIDC Authorization Code + PKCE через Keycloak, API проверяет подпись, `issuer`, `audience` и срок действия токена. Агент предъявляет отдельный токен Knowledge; в базе хранится лишь его хеш. Ошибки доступа возвращают `401` без личности и `403` без требуемого полномочия.

| Операция | Право | Результат |
| --- | --- | --- |
| `GET /me`, `GET /people` | Подтверждённая личность; список людей — `admin` или `owner` | Текущий участник и люди, уже входившие в Trellis. |
| `GET /projects`, `GET /projects/:id` | Свои проекты; `admin` видит метаданные всех | Каталог и метаданные без обхода прав на файлы. |
| `POST /projects`, `PATCH /projects/:id`, `POST /projects/:id/archive`, `POST /projects/:id/retry` | `admin` | Создание, изменение метаданных/владельца, архивация, повтор создания Git. Создание принимает `name`, `description`, `ownerPersonId`. |
| `GET /projects/:id/users`, `PUT/DELETE /projects/:id/users/:personId`, аналогичные пути `/agents/:agentId` | `owner` | Просмотр и изменение назначений. |
| `GET/POST /agents`, `PATCH /agents/:id`, `GET/POST /agents/:id/tokens`, `DELETE /agents/:id/tokens/:tokenId` | Создание и управление — `admin`; список имён доступен `owner` | Управление агентами; новый секрет возвращается один раз. |
| `GET /projects/:id/repository`, `GET /projects/:id/commits`, `GET /projects/:id/commits/:oid/tree`, `GET /projects/:id/commits/:oid/blob` | `owner`, `user` или назначенный агент | Точная ревизия `main`, история, дерево и содержимое файла. |

Чтение `:oid` требует полного commit ID, достижимого из текущего `main`. `tree` и `blob` принимают относительный `?path=`, история — `?skip=` с размером страницы 50. Путь файла не содержит пустых, `.` и `..` сегментов; Git symlink не разыменовывается. API не принимает серверные пути Git. Отсутствующий или чужой коммит возвращает `404` после проверки проектного доступа. Чтение текстового blob ограничено 1 МиБ.

Первый этап не принимает коммиты, ветки предложений и рабочие файлы. Операции принятия Framework, Git HTTPS, webhook и Runtime остаются отдельными контрактами. UI показывает стартовый пустой коммит до появления способа публикации.
