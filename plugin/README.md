# Trellis

Рабочая область Trellis внутри VS Code / Cursor.

## Использование

1. Установите `trellis-0.2.1.vsix` через **Extensions: Install from VSIX…**.
2. Откройте значок **Trellis** в боковой панели.
3. Выберите папку проекта. Проверка доступности и журнал доступны кнопками в заголовке панели.

Боковая панель показывает корневые папки workspace в порядке Explorer: имя, полный путь и доступность. «Добавить папку» вызывает штатный диалог редактора; отмена сохраняет текущий список. Состав и восстановление сохранённого workspace остаются у редактора.

Выберите проект в боковой панели или командой **Trellis: Выбрать проект** из палитры. Выбор определяется URI папки: одноимённые проекты различимы по полному пути. Боковая панель также показывает выбранную папку в Explorer. Если убрать её из workspace средствами редактора, выбор сбрасывается. После перезапуска выберите проект заново.

Для недоступной папки отображаются причина и следующее действие. После восстановления диска или разрешений используйте **Проверить доступность папок**. Проверка ограничена пятью секундами; её журнал доступен командой **Trellis: Открыть журнал** и содержит последние 100 записей текущего окна. Нелокальные URI видны в списке с объяснением ограничения анализа.

Вкладка зарезервирована под Grafel и пока остаётся пустой. Она открывается только командой **Trellis: Открыть Trellis** из палитры. Повторная команда активирует существующую вкладку; автоматически она не открывается.

Версия 0.2.1 реализует первый этап MVP — папки workspace и выбор проекта. Grafel, индексация, граф и MCP появятся на следующих этапах. Доступность папки ещё не означает наличие индекса или поддержку её языка. Расширение не скачивает компоненты, не запускает внешние процессы и не отправляет данные проекта.

## Сборка

Нужны Node.js 22+ и npm. Из директории `plugin/`:

```powershell
npm ci
npm run check
npm run package
```

Результат: `plugin/trellis-0.2.1.vsix`. Для этой сборки не требуется инициализация submodule Grafel. Пакет содержит скомпилированное расширение и локальные ресурсы; исходники тестов и зависимости разработки исключены.

## Проверка в редакторе

```powershell
$env:TRELLIS_TEST_EXECUTABLE = 'C:\path\to\Code.exe'
npm test
```

Для Cursor укажите путь к `Cursor.exe`. Без переменной тестовый инструмент скачивает стабильный VS Code. Тесты используют отдельный временный профиль и каталог расширений. Проверяются окно с одной папкой, штатное добавление/отмена, выбор, диагностика, пустой workspace, перезапуск с сохранённым workspace и работа оболочки без доверия.

Playwright подключается к Chromium тестового окна через временный loopback-порт. Для автоматизации штатного диалога папок в этом профиле включён `files.simpleDialog.enable`; пользовательский профиль не меняется. Проверки сравнивают реальные панели и сохраняют PNG, JSON-результаты и журналы хоста по выведенному временному пути. Переходы workspace, недоступность и асинхронные гонки дополнительно проверяются через API Extension Host. UI-тесты требуют англоязычный интерфейс редактора (собственный UI Trellis остаётся русским).

Для проверки распакованного VSIX можно дополнительно задать `TRELLIS_TEST_EXTENSION_PATH` — путь к директории `extension/` внутри распакованного пакета.

В корневом репозитории доступна конфигурация **Run Trellis** для запуска расширения через F5. Она собирает плагин и запускает Extension Development Host в текущем редакторе (`Code.exe` или `Cursor.exe`). Установленные пользовательские расширения отключены в окне разработки; разрабатываемый Trellis загружается из `plugin/`. Исходное окно проекта остаётся открытым: одно дополнительное окно Extension Development Host при F5 — штатное поведение.

После открытия выберите значок Trellis в боковой панели. Изменения исходников требуют повторного запуска; для непрерывной компиляции используйте `npm run watch`.
