# Trellis Registry

Распространение версий агентов и навыков.

## Целевой пакет

Один пакет соответствует одной ограниченной задаче. Его исходные определения находятся рядом с доменными контрактами [Framework](../trellis-framework/domains/module.md): `AGENTS.md` описывает процедуру, отдельные YAML-каталоги содержат навыки, а YAML-определение агента задаёт вход, выход, требуемый способ исполнения и детерминированные гейты.

CI/CD собирает самодостаточный пакет из выбранной ревизии Framework и доставляет его в Registry. Сборка разрешает ссылки на навыки, целевую схему и все её `$ref`-зависимости и включает их содержимое в пакет. Tasks проверяет данные по зафиксированным схемам пакета, а Runtime передаёт агенту текст с раскрытыми ссылками, сформированный из этих же схем. Пакет хранит исходную ревизию, точную версию и контрольную сумму; изменение содержимого требует новой версии.

В целевом цикле [Tasks](../trellis-tasks/module.md) выбирает опубликованный пакет при создании задачи и закрепляет его точную версию и контрольную сумму. [Runtime](../trellis-runtime/module.md) получает этот пакет для исполнения. Локальная работа с авторскими определениями Framework не требует Registry; он не является посредником чтения YAML-документов проекта.

Пакет задаёт поведение агента, но не его учётную запись и не проектные права: ими владеет [Knowledge](../trellis-knowledge/module.md).

[Граница](module.md) отделяет распространение от исполнения и принятия знаний. [Пакет product](../trellis-framework/domains/product/agent/module.md) подключён в конфигурации Framework, а в других доменах пока действуют встроенные навыки. Сборка пакета, доставка через CI/CD, формат транспортного API и работающий сервер каталога ещё не реализованы.
