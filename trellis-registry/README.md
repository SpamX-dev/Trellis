# Trellis Registry

Каталог и система распространения версионируемых пакетов агентов и Skills для Trellis Runtime.

## Назначение

Trellis Registry предоставляет пакеты, реализующие Agent Role и Skill по контрактам Trellis Framework. Registry отделяет публикацию и выбор версий от исполнения Engineering Work.

Минимальная область каталога включает agent packages и skill packages. Распространение исполняемых файлов Runtime, MCP-серверов и иных типов пакетов не входит в базовый контракт Registry.

## Ответственность

- Публикация и хранение версий пакетов агентов и навыков.
- Каталогизация пакетов по идентификаторам, ролям, возможностям и требованиям совместимости.
- Проверка манифестов по схемам Trellis Framework.
- Разрешение версий, зависимостей и ограничений совместимости.
- Предоставление метаданных и содержимого пакетов для загрузки.
- Проверка целостности содержимого и сохранение сведений о происхождении пакета.
- Возможность фиксировать точные версии зависимостей для воспроизводимой конфигурации запуска.

Опубликованная версия должна однозначно определять содержимое пакета. Изменение содержимого требует новой версии.

## Вне области проекта

- Запуск агентов и выполнение WorkItem.
- Хранение Knowledge State, документов проекта и Semantic Backlog.
- Формирование Knowledge Slice для конкретной задачи.
- Применение ChangeSet и принятие решений Human/Policy Gate.
- Выдача фактических разрешений на инструменты, MCP и внешние сервисы.
- Интерфейс IDE и управление установленным Runtime.

Проверка пакета подтверждает соответствие формату и целостность. Она не подтверждает инженерную корректность будущих результатов агента.

## Основные понятия и интерфейсы

| Понятие или интерфейс | Назначение |
| --- | --- |
| Agent package | Реализация Agent Role: поддерживаемые WorkItem, необходимые Skills и контракты результатов. |
| Skill package | Процедура работы, retrieval policy, правила валидации и требования к Evidence. |
| Package manifest | Идентификатор, версия, тип пакета, зависимости, ограничения совместимости и требуемые возможности. |
| Package identity | Идентификатор и точная версия с данными для проверки целостности содержимого. |
| Publish | Регистрация новой версии с проверкой манифеста и метаданных. |
| Search / inspect | Поиск пакета и чтение его контрактов, зависимостей и совместимости. |
| Resolve | Выбор конкретных версий, удовлетворяющих заявленным ограничениям. |
| Download / verify | Получение содержимого и проверка его целостности. |

Названия операций концептуальные. Формат манифеста, схема версий и транспорт API подлежат спецификации.

Agent Role определяет ответственность и допустимую работу, а не только prompt или persona. Skill определяет процедуру и контракт результата, а не только текст инструкции.

## Пример пакета

Концептуальное содержимое agent package:

```text
integration-architect
  role: Integration Architect
  inputs: WorkItem for Integration Design
  skills:
    integration-design
    dependency-analysis
  knowledge scope: relevant integration Knowledge Slice
  outputs:
    proposed ChangeSet
    downstream requirements for Service Design
    Derivation / Evidence
```

Пакет декларирует требуемую область знаний, возможности инструментов и формат результата. Конкретный Knowledge Slice и доступ к инструментам определяются при выполнении WorkItem.

## Процесс распространения

```text
Package author
  -> publish package version
  -> validate manifest and package integrity
  -> Registry

Runtime or VS Code
  -> inspect and resolve package dependencies
  -> download and verify exact versions
  -> configure Runtime
  -> Runtime executes WorkItem
```

Runtime включает идентификаторы и точные версии использованных пакетов в Derivation/Provenance. Эти сведения сохраняются в Trellis Knowledge вместе с результатами Engineering Work.

Зависимости пакетов отличаются от downstream requirements. Первые необходимы для загрузки агента или Skill; вторые возникают как результат инженерной работы и поступают в Semantic Backlog соответствующих областей.

## Связь с компонентами Trellis

| Компонент | Взаимодействие |
| --- | --- |
| `trellis-framework` | Определяет контракты Agent Role, Skill, манифестов и совместимости с протоколом. |
| `trellis-runtime` | Разрешает и загружает пакеты, затем исполняет их в контексте WorkItem. |
| `trellis-knowledge` | Хранит Knowledge State и ссылки на использованные версии пакетов в Provenance. |
| `trellis-vscode` | Предоставляет выбор, установку и обновление пакетов для настроенного Runtime. |

Registry не хранит инженерную multi-repo traceability. Он предоставляет точные идентификаторы пакетов, необходимые для трассировки исполнения между проектами и репозиториями.

## Пример структуры

Целевая организация репозитория сервиса:

```text
trellis-registry/
  catalog/       # Метаданные и поиск пакетов
  manifests/     # Обработка манифестов Framework
  publishing/    # Приём и проверка версий
  resolution/    # Зависимости и совместимость
  distribution/  # Выдача содержимого пакетов
  api/           # Интерфейсы каталога и распространения
```

## Статус проекта

Стадия по текущей концепции: проектирование. README описывает целевую архитектуру. Формат пакетов, правила публикации, модель доверия и API подлежат спецификации; публичный каталог и команды установки не заявлены.
