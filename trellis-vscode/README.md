# Trellis VS Code

Расширение Visual Studio Code для настройки Trellis, выполнения инженерной работы и просмотра изменений знаний.

## Назначение

Trellis VS Code предоставляет локальную интеграцию, доставку компонентов и пользовательский интерфейс поверх Trellis Framework, Runtime, Knowledge и Registry.

Расширение связывает рабочую среду разработчика с Semantic Backlog, текущим WorkItem, Knowledge Slice и результатами Engineering Work.

## Ответственность

- Первичная настройка Trellis для workspace.
- Доставка, установка, обновление и конфигурация совместимого Runtime либо подключение к доступному экземпляру.
- Выбор, установка и обновление пакетов агентов и Skills из Registry.
- Настройка подключения к Trellis Knowledge и Registry.
- Доставка и конфигурация локальных MCP-компонентов из настроенных источников, подключение внешних MCP-серверов.
- Запуск и остановка локальной среды через интерфейсы Runtime.
- Выбор WorkItem из Semantic Backlog, запуск работы и отображение её состояния.
- Просмотр Knowledge Slice, документов, semantic diff, document/artifact diff и Evidence.
- Интерфейс Human/Policy Gate: approve, amend и reject с передачей решения через сервисные контракты.
- Просмотр downstream requirements, Derivation/Provenance и multi-repo traceability.

## Вне области проекта

- Собственный agent execution harness и встроенная реализация инженерных ролей.
- Владение каноническим Knowledge State и отдельная база инженерных знаний внутри расширения.
- Собственный каталог или формат пакетов агентов и Skills.
- Реализация доменных правил вне контрактов Trellis Framework.
- Прямое применение изменений в обход Trellis Knowledge и Human/Policy Gate.
- Реализация MCP-протокола исполнения, зависящая от VS Code.
- Построение AST/LSP-модели, анализ исходного кода и замена средств разработки IDE.

Локальные настройки и кэш не являются источником принятого Knowledge State.

## Основные понятия и интерфейсы

| Понятие или интерфейс | Назначение |
| --- | --- |
| Workspace configuration | Подключения к сервисам, выбранный Runtime, пакеты, параметры MCP и связи с репозиториями. |
| Semantic Backlog view | Входящие изменения и обязательства инженерной области. |
| WorkItem view | Входы, задача, Agent Role, Skills, базовая ревизия и состояние выполнения. |
| Knowledge Slice view | Контекст работы, ограничения, источники и сведения о полноте данных. |
| ChangeSet review | Изменения знаний и документов, проверки, downstream requirements и Evidence. |
| Human/Policy Gate actions | Передача решения пользователя и отображение требований политики. |
| Trace view | Цепочки Derivation/Provenance от исходного изменения до реализации и проверок. |
| Runtime client | Настройка исполнения, запуск, отмена и получение событий работы. |
| Knowledge client | Чтение Knowledge State, документов, ревизий, diff и трассировки. |
| Registry client | Поиск и разрешение версий пакетов агентов и Skills. |

Интерфейсы концептуальные. Названия команд, настроек и представлений расширения подлежат спецификации.

## Пользовательский процесс

```text
Configure Trellis workspace
  -> connect Knowledge and Registry
  -> install or connect Runtime
  -> select Agent and Skill package versions
  -> configure Tools / MCP
  -> select WorkItem
  -> inspect Knowledge Slice
  -> run Engineering Work through Runtime
  -> review proposed ChangeSet and downstream requirements
  -> submit Human/Policy Gate decision
  -> display application result and Knowledge State revision
```

Approve передаёт решение для конкретной версии ChangeSet. Новая ревизия отображается после подтверждения применения Trellis Knowledge. Amend возвращает предложение на изменение и повторную проверку; reject сохраняет решение об отклонении.

Для существующей системы представление работы показывает, какие решения сохраняют актуальность, какие требуют review и какие downstream requirements изменились.

## Доставка и MCP

Источники поставки разделены по типу компонента:

| Компонент | Источник и управление |
| --- | --- |
| Runtime | Настроенный источник дистрибутива или доступный экземпляр Runtime. |
| Agents / Skills | Версионированные пакеты Trellis Registry. |
| MCP | Настроенные источники локальных компонентов или адреса внешних серверов. |

Расширение предоставляет установку, параметры подключения и управление локальной средой. Runtime управляет использованием MCP-инструментов при выполнении WorkItem и lifecycle подключений. Реализации MCP-серверов могут поставляться отдельно.

Registry не предполагается универсальным источником Runtime или MCP-пакетов. Конфигурация расширения должна сохранять выбранные версии и требования совместимости.

## Multi-repo traceability

Workspace может быть связан с несколькими репозиториями. Расширение показывает связи требований, решений и компонентов с implementation tasks, репозиториями, коммитами, review и Evidence.

Структура workspace не определяет архитектурные границы системы. Трассировка читается из Trellis Knowledge и может выходить за пределы локально открытых репозиториев.

## Связь с компонентами Trellis

| Компонент | Взаимодействие |
| --- | --- |
| `trellis-framework` | Общие схемы и контракты данных, отображаемых в UI. |
| `trellis-runtime` | Выполнение WorkItem, доступ к инструментам, события работы и оркестрация gate. |
| `trellis-knowledge` | Каноническое состояние, документы, ChangeSet, ревизии и трассировка. |
| `trellis-registry` | Каталог, совместимость и распространение агентов и Skills. |

Остальные компоненты Trellis могут использоваться без расширения VS Code.

## Пример структуры

Целевая организация репозитория:

```text
trellis-vscode/
  extension/   # Активация и команды VS Code
  setup/       # Доставка и конфигурация компонентов
  clients/     # Клиенты Runtime, Knowledge и Registry
  views/       # WorkItem, ChangeSet, документы и трассировка
  workspace/   # Локальная конфигурация и связи с репозиториями
```
