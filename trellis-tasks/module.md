# Граница Trellis Tasks

## Назначение

Tasks организует жизненный цикл задач агентов между человеком, [Registry](../trellis-registry/module.md), [Runtime](../trellis-runtime/module.md) и [Knowledge](../trellis-knowledge/module.md). Он принимает задачу человека или событие принятого изменения и назначает исполнение Runtime.

## Ответственность

- Создание задачи в рамках проекта, выбор последней опубликованной версии пакета агента и фиксация её точной версии, контрольной суммы содержимого и исходных ревизий для запуска. Новая публикация не меняет уже созданную задачу.
- Координация детерминированных гейтов по библиотечным проверкам Framework: проверка входа и отчёта, учёт результата проверки Git-снимка от Knowledge. Задача завершается только после успешного прохождения обязательных гейтов.
- Хранение состояния задачи, истории попыток, вопросов агента, ответов человека и журнала исполнения; предоставление этих сведений [Web](../trellis-web/module.md).
- Назначение работы Runtime, координация повторов и отмены с сохранением идентичности задачи.
- Обработка события `documents.accepted` по явно объявленным подпискам на конкретных агентов. Повтор события не создаёт независимую задачу для той же реакции.
- Связь задачи с итоговыми артефактами и предложениями в Knowledge без самостоятельного принятия изменений.

## Зависимости и границы

[Registry](../trellis-registry/module.md) предоставляет опубликованные пакеты; Tasks закрепляет выбранный пакет при создании задачи, а Runtime получает его для исполнения. [Knowledge](../trellis-knowledge/module.md) подтверждает проектные права и предоставляет разрешённые снимки. Имя пакета и поле домена сами по себе не предоставляют доступа к проекту.

Tasks владеет состоянием задачи и диалогом с человеком. Runtime исполняет назначенную попытку и сообщает её ход; Knowledge хранит итоговые артефакты, предложения и решения человека. Завершение исполнения не означает принятия предложенных документов.

Зафиксированная версия библиотечных проверок определяет машинные гейты задачи; соответствующий файловый комплект объясняет агенту модель и процедуру. Проверка гейта не выдаёт агенту прав, не заменяет содержательное решение человека и не переносит результат на другую версию пакета.

Внутренняя реакция на `documents.accepted` отделена от внешних [webhook](../trellis-knowledge/webhooks/module.md) об изменениях Git-веток. Граф ссылок помогает выбрать контекст, но не создаёт подписки на запуск.
