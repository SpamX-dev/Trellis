# Trellis Tasks

Tasks связывает запрос человека или принятое изменение документов с исполнением агента. [Граница модуля](module.md) определяет владение состояниями задач, вопросами и ответами, назначением работы Runtime и повторной обработкой событий.

В целевом цикле Tasks выбирает опубликованный пакет в [Registry](../trellis-registry/module.md), закрепляет его для задачи и назначает исполнение [Runtime](../trellis-runtime/module.md). [Knowledge](../trellis-knowledge/module.md) проверяет проектные права и хранит итоговые артефакты и предложения; [Web](../trellis-web/module.md) показывает ход работы и принимает ответы человека.

## Целевые гейты задачи

Один пакет выполняет одну ограниченную задачу. Tasks выступает orchestrator: берёт из закреплённого пакета YAML-объявления гейтов, проверяет вход до назначения исполнения и выход до завершения задачи. Для проверок формы используются включённые в пакет схемы; для проверки предложения и публикации ветки Tasks получает результат от Knowledge. Неуспешный обязательный гейт не позволяет перевести задачу в завершённое состояние.

Для [пакета проверки комплаенса](../trellis-framework/examples/compliance-check-agent-package/module.md) Tasks закрепляет проект и базовые ревизии, передаёт область чтения и разрешённые пути записи. Перед завершением Knowledge должен подтвердить commit ветки, сравнить все изменённые пути с разрешёнными, проверить полный итоговый снимок и изменённые оценки по схеме навыка. ChangeSet выводится из diff и не повторяется в выходе агента.

[Пакет product](../trellis-framework/domains/product/agent/module.md) принимает список текущих требований, который может быть пустым, и использует те же Git-гейты для ограничения изменённых путей и проверки итогового снимка по составной схеме домена.

`AGENTS.md` задаёт агенту короткую процедуру в пределах задачи, но не является источником машинных условий. Смысловые критерии `x-trellis-checks` возвращаются отдельным отчётом и не считаются детерминированными гейтами. При реакции на `documents.accepted` целевая конфигурация указывает конкретного агента, чтобы Tasks не выбирал его по имени домена предположительно.

Сейчас [конфигурация доменов](../trellis-framework/domains.yaml) связывает домен с одним агентом и доменными `on_change`. Сервис задач, очередь, интерфейс задач и описанные гейты ещё не реализованы.
