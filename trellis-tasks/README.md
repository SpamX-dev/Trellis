# Trellis Tasks

Tasks связывает запрос человека или принятое изменение документов с исполнением агента. [Граница модуля](module.md) определяет владение состояниями задач, вопросами и ответами, назначением работы Runtime и повторной обработкой событий.

В целевом цикле Tasks выбирает опубликованный пакет в [Registry](../trellis-registry/module.md), закрепляет его для задачи и назначает исполнение [Runtime](../trellis-runtime/module.md). [Knowledge](../trellis-knowledge/module.md) проверяет проектные права и хранит итоговые артефакты и предложения; [Web](../trellis-web/module.md) показывает ход работы и принимает ответы человека.

## Целевые гейты задачи

Один пакет выполняет одну ограниченную задачу. Tasks проверяет вход до назначения исполнения и отчёт до завершения задачи. Для `completed` он получает через Knowledge точный commit и содержимое продуктовой области, затем вызывает проверки [Framework](../trellis-framework/plan.md). Неуспешный обязательный гейт не позволяет перевести задачу в завершённое состояние.

Для первого product-сценария вход содержит `{ request: string }`; отчёт исполнителя содержит статус и резюме. `completed` подтверждается только после проверки Git-снимка и связей документов. `needs_input` и `failed` являются допустимыми отчётами, но не успешным завершением. Документы и ChangeSet не дублируются в отчёте.

Инструкция агента описывает процедуру, но машинные условия определяют библиотечные гейты. Реакции на `documents.accepted` остаются ответственностью Tasks. Сервис задач, очередь, интерфейс задач и описанные гейты ещё не реализованы.
