# Проверка одного продукта на комплаенс

## Задача

Оцени один продукт по выбранному каталогу ограничений на закреплённом снимке проекта. [Вход](input.schema.yaml) задаёт `product_id`, список `catalog_requirement_ids`, доступные для чтения домены и разрешённые пути записи. Проект, базовая ревизия документов и ревизия Framework приходят из задачи Tasks.

## Работа

1. Прочитай продуктовые документы, выбранные ограничения с процедурами и существующие оценки из разрешённых доменов. Применяй навык `assess-product` и приложенную к нему схему оценки.
2. Для каждой пары продукт–ограничение создай или обнови одну оценку. Зафиксируй базовую ревизию в `evaluated_revision`. Если подтверждений не хватает, сохрани `unknown` и укажи пробелы.
3. Запиши документы только в `allowed_changes.paths` или под `allowed_changes.prefixes`, сохраняя границу домена `compliance-check`. Сделай commit и push в ветку предложения.
4. Верни опубликованную ветку и точный commit по [схеме выхода](output.schema.yaml). Tasks применит гейты из `agent.yaml`: Knowledge сравнит commit с базовой ревизией, проверит изменённые пути, полный итоговый снимок и изменённые оценки по схеме навыка. ChangeSet выводится из Git diff и не дублируется в выходе.

Если нет доступа к документам, публикация или проверка не прошла, сообщи причину и не объявляй задачу завершённой. Принятие предложения выполняет человек.
