# Сервис уведомлений: учебный сценарий

Пример показывает три домена на одном наборе документов. Все источники, процедуры и ревизии условные; внешние системы и реальные нормативные требования не проверялись.

## Исходные сведения

Учебное интервью: владелец продукта хочет отправлять пользователю уведомления по email после подтверждения адреса. Адрес и состояние подтверждения сохраняются. Запрос подтверждения должен передаваться почтовому сервису в течение пяти секунд для 95% запросов при нагрузке до 10 запросов в секунду и доступном почтовом сервисе.

Учебная внутренняя политика: использование email требует верификации сценария службой качества по процедуре VP-001. Материалы фактического выполнения процедуры не предоставлены.

Ограничение применимо по известному факту обработки email. Выполнение остаётся unknown: описание проверки и требование её пройти не заменяют результат.

## Изменение

[ChangeSet](changeset.yaml) заменяет допустимое время отправки запроса подтверждения с пяти на три секунды. Изменение меры не заявляет, что продукт уже выполняет новое требование.

`example-base` — имя исходного набора файлов в этом примере, `example-framework` — условное имя показанных контрактов. В реальном запуске используются точные идентификаторы снимков.

Проверка ChangeSet накладывает его на исходные документы в памяти. Применение человеком и доставка события описаны в контракте и этим примером не исполняются. После принятия изменения нужна новая оценка; старая CHECK-001 остаётся заключением об example-base.

## Проверить

Из корня репозитория:

```sh
npm run check
npm test
```

Проверка охватывает схемы, конфигурацию, все одиннадцать документов, ссылки, локальные переходы процесса и предложение правки.
