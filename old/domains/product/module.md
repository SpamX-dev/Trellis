# Домен продуктовых требований

## Назначение

Домен описывает границу продукта, роли, пользовательские цели, поведение, качества, бизнес-правила, процессы и предметные данные.

## Контракты

- [Схемы](schema/module.md) определяют восемь типов документов в отдельных файлах.
- [Агент](agent/module.md) готовит предложение документов по запросу и текущим требованиям.
- [Представление](render/module.md) ограничивает будущие правила отображения.

| Тип | Ответственность |
| --- | --- |
| [product](schema/product.schema.yaml) | Назначение и граница продукта. |
| [actor](schema/actor.schema.yaml) | Роль человека или внешней системы. |
| [user-story](schema/user-story.schema.yaml) | Цель и польза для роли. |
| [functional-requirement](schema/functional-requirement.schema.yaml) | Проверяемое поведение продукта. |
| [non-functional-requirement](schema/non-functional-requirement.schema.yaml) | Свойство, мера, целевое значение и условия. |
| [business-rule](schema/business-rule.schema.yaml) | Ограничивающее правило предметной области. |
| [business-process](schema/business-process.schema.yaml) | Цель, шаги и переходы процесса. |
| [business-object](schema/business-object.schema.yaml) | Понятие и смысл его атрибутов. |

## Группировка

Поле `group` содержит имена смысловых групп, например `group: [уведомления, персональные-данные]`. Оно доступно всем типам продуктового домена и позволяет отнести документ к нескольким темам независимо от его пути.

Группы задаются непосредственно в документах, без отдельного каталога или сущностей групп. Отсутствующее поле или пустой массив означает, что группы не назначены. Имена сравниваются точно, с учётом регистра; одинаковое написание объединяет документы при поиске и представлении.

Принадлежность группе не заменяет содержательные ссылки между требованиями и сама по себе не создаёт типизированного ребра. Поиск по имени группы находит кандидатов; точная принадлежность определяется значениями массива `group`.

## Границы

Требование не является доказательством реализации. Предметный объект не задаёт физическую схему БД. Внешние ограничения описывает домен комплаенса; оценку соответствия — домен проверки.

Вход агента может содержать пути текущих требований на закреплённой ревизии; отсутствие списка или пустой список допустимы для первой итерации. Выход указывает ветку и commit предложения. Состав изменений может включать любое подмножество US, FR, NFR, BR, BP и BD, а также документы продукта и ролей, если они требуются запросом; итоговые документы проверяются по схемам каталога.

Шаги процесса имеют локальные ключи; независимая глобальная идентичность им не приписывается. Поля со ссылками и допустимые цели определяются только схемой.
