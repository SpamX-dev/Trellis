# Документ и его хранение

## Источник знаний

Принятое состояние базы — согласованный снимок YAML-документов. Документ представляет содержательную единицу чтения, изменения и принятия. Один процесс может содержать несколько шагов; каждый вложенный объект не требует собственного файла.

Рендер, граф и поисковые индексы вычисляются из документов. Они могут быть удалены и получены заново. Их ручное изменение не изменяет принятые знания.

## Форма и YAML-профиль

В каждом файле ровно один YAML-документ с объектом на верхнем уровне. Первая строка имеет вид:

```yaml
id: "FR-001"
```

Идентификатор — строка, в том числе для числового вида `"001"`. Кавычки и расположение на первой строке являются соглашением сериализации для точного текстового поиска. JSON Schema проверяет значение, а загрузчик отдельно проверяет эту запись.

Тип задаётся полем `type` и выбирает определение в схеме домена. Обязательные поля и допустимые значения находятся только в схеме. `name` — название, `summary` — краткое описание, `sources` — происхождение, `gaps` — открытые вопросы.

Используется YAML 1.2 в JSON-совместимом подмножестве: строковые ключи, строки, конечные числа, boolean, null, массивы и объекты. Дубли ключей, явные теги, anchors, aliases и merge keys запрещены. Порядок ключей не меняет смысл данных. Основной текст удобно хранить блоком `|`.

Отсутствие необязательного поля означает отсутствие зафиксированного значения. `gaps` не позволяет обходить обязательность поля. Если обязательный факт неизвестен, автор сохраняет незавершённую работу как черновик и уточняет её до принятия.

## Размещение и поиск

Корень базы документов отделяется от контрактов, истории и рабочих предложений. Конвенция размещения:

```text
documents/
  product/<type>/<id>.yaml
  compliance/<type>/<id>.yaml
  compliance-check/<type>/<id>.yaml
```

Домен и тип задают область поиска. Внутри типа допустимы тематические подкаталоги; имя файла сохраняет вид `id.yaml`. Идентификатор уникален во всём снимке базы и не зависит от пути. Размещение проверяется по конфигурации доменов; переименование типа требует явного изменения документа, простое перемещение не меняет id.

Поиск принятого документа не требует сервера или постоянного индекса:

```sh
rg --crlf -l -g '*.yaml' '^id: "FR-001"$' documents
```

Ноль результатов означает отсутствие документа, один — найденный документ, несколько — конфликт идентичности. Рабочие предложения и исторические снимки не включаются в этот поиск. После поиска значение проверяется разбором YAML.

## Ссылки и граф

Ссылка — строковый идентификатор. Поле или элемент массива со ссылкой помечается в схеме аннотацией `x-trellis-ref`:

```yaml
actor_ref:
  $ref: ../../contracts/common.schema.yaml#/$defs/id
  description: Роль, от лица которой заявлена цель.
  x-trellis-ref:
    targets: [actor]
    relation: performed-by
```

Узел графа соответствует документу. Каждая такая ссылка даёт направленное ребро от документа к цели с именем `relation`. Источник ребра включает путь поля в документе; обратные ссылки выводятся. Обычная строка с похожим id без аннотации не становится ребром.

В начальной модели шаги процесса остаются вложенными данными с локальными `key`; `next_steps` указывает на эти ключи, а не на документы базы. Локальные ключи и переходы проверяются отдельно. Если впоследствии понадобится адресовать шаг извне, его идентичность должна быть явно определена контрактом.

Граф строится детерминированно по документам и схемам, без повторного извлечения смысла LLM. Новая смысловая связь, найденная агентом, сначала предлагается как изменение документа.

## Снимки и полнота

Ссылка разрешается в выбранном снимке базы. Для исторической оценки используется её `evaluated_revision`; открытие старой оценки на новом состоянии не делает её актуальной. Изменение источников требует пересмотра вывода.

Построение графа фиксирует ревизию документов, ревизию Framework и область выборки. Частичный граф не доказывает отсутствие связей за пределами своей области. Проверка принятия рассматривает итоговый набор документов целиком.

Физическое хранение истории допускает Git. Атомарное изменение указателя ветки и согласованное чтение снимка должны обеспечиваться реализацией; простая последовательная запись нескольких файлов не объявляется транзакцией.
