# Предложение и принятие изменения

## Предложение

Агент работает с согласованным исходным снимком и готовит ChangeSet по [схеме](changeset.schema.yaml). Поля `base_revision` и `framework_revision` фиксируют документы и контракты, на которых основана работа.

Каждая операция содержит относительный `path` и `document_id`:

- `add` — новый путь и новый идентификатор; содержит полный `document`.
- `replace` — существующий документ на этом пути с тем же идентификатором; содержит полный новый `document`.
- `remove` — существующий документ с указанным идентификатором; не содержит `document`.

Путь использует `/`, не начинается с корня или диска, не содержит `.`, `..`, пустых сегментов и остаётся внутри каталога документов. При работе с диском проверяется также разрешённый путь: symlink не должен выводить операцию за границы базы.

Один путь изменяется один раз в предложении. Перемещение выражается удалением старого пути и добавлением нового с тем же id: оно допустимо, если в итоговом наборе id встречается один раз. Добавление с id существующего неудаляемого документа запрещено.

## Проверка

1. Разобрать YAML без дублирующихся ключей и других запрещённых конструкций.
2. Проверить предложение по JSON Schema.
3. Наложить все операции на базовый снимок в памяти.
4. Проверить доменные схемы всех итоговых документов.
5. Проверить размещение, уникальность id, существование и типы целей ссылок.
6. Проверить доменные инварианты, которые нельзя выразить обычной схемой: локальные ключи и переходы шагов процесса.
7. При необходимости запросить содержательную оценку по критериям схем.

Проверка рассматривает итоговую совокупность: новый документ может ссылаться на другой документ того же предложения. Удаление цели без изменения входящих ссылок отклоняется. Операции не применяются по очереди к принятой базе во время проверки.

Детерминированная ошибка содержит `code`, `file`, `pointer` и `message`. Базовые коды: `yaml-invalid`, `schema-invalid`, `id-duplicate`, `ref-not-found`, `ref-type-invalid`, `layout-invalid`, `revision-conflict`, `operation-invalid`. AI-вывод хранится отдельно и может быть неопределённым.

## Решение человека

Клиент показывает исходный и новый документ, diff, результаты проверок и пробелы. Человек применяет либо отклоняет конкретное предложение.

Форма записи предложения не даёт автору права применения. Решение привязывается к идентификатору предложения, хешу его содержимого, базовому снимку и ревизии Framework. Изменённое после просмотра предложение требует нового решения.

Перед применением Knowledge повторно проверяет актуальность базового снимка и условия целостности. Конфликт возвращается автору; скрытое слияние не выполняется. Повтор применения того же принятого предложения возвращает прежний результат, а использование того же id для иного содержимого отклоняется.

Отказ сохраняет причину и не меняет документы. Пользователь может продолжить работу в новом предложении.

## Публикация и события

Knowledge публикует весь принятый снимок согласованно, сохраняет решение и только затем создаёт событие `documents.accepted` с идентификатором, новой ревизией и перечнем изменённых доменов и документов.

События запускают только явно заданные `on_change` в [конфигурации](../domains.yaml). Граф ссылок помогает определить контекст, но не заменяет подписку.

Для домена проверки комплаенса:

- Изменение продукта требует пересмотра применимости ограничений к затронутым продуктам.
- Изменение каталога комплаенса требует пересмотра затронутых ограничений для продуктов выбранной базы, даже если связей с ними ещё нет.
- При недостаточном контексте результат остаётся `unknown`.
- Повтор одного события для одного домена продолжает ту же работу.
- Новое заключение само является предложением и проходит принятие.

## Файловая работа

Обычное редактирование файлов допустимо в отдельной рабочей копии или области предложения. Оно не является самостоятельным способом публикации принятого снимка. Чтение и поиск остаются обычными файловыми операциями.

Сервисный транспорт, очередь событий и способ атомарной публикации — ответственность реализации. Исполняемая проверка примеров моделирует только проверки данных и наложение предложения в памяти.
