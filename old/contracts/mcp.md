# Граница MCP

MCP предоставляет доступ к тем же контрактам, с которыми можно работать локально. Чтение каталогов и поиск документов по id не требуют MCP.

## Операции

| Операция | Вход | Результат |
| --- | --- | --- |
| `get_domain` | Имя домена, ревизия Framework. | Схема, агент, навыки, критерии, рендер и ссылки на примеры. |
| `get_schema` | Имя домена или зарегистрированного типа, ревизия Framework. | Соответствующая схема и её зависимости. |
| `propose_changes` | ChangeSet. | Сохранённое предложение и его хеш либо ошибки. |
| `validate_changes` | Точная версия предложения. | Детерминированный отчёт по итоговому набору документов. |
| `apply_changes` | Точная версия предложения и решение человека. | Принятая ревизия либо конфликт или отказ. |
| `reject_changes` | Точная версия предложения и причина. | Запись об отклонении. |

Имена обозначают контракт операций; они не заявляют наличие работающего сервера.

## Правила

JSON Schema используется для формы входных данных. Проверка существования ссылок, конфликтов и принятия остаётся на стороне Knowledge. Knowledge подтверждает личность из контекста вызова и проверяет проектные права; ограничения среды могут дополнительно сузить доступ. Переданные агентом поля `domain` и `actor` не выдают разрешений и не заменяют подтверждение личности.

`get_schema` разрешает только зарегистрированные локальные схемы, не произвольные пути или сетевые адреса. Получение соседней схемы помогает интерпретации и само по себе не даёт права записи в соседний домен.

Подготовка предложения не означает его применения. Долгая AI-проверка может исполняться Runtime отдельно; результат привязывается к хешу проверенного предложения. Устаревший отчёт не переносится автоматически на новую редакцию.
