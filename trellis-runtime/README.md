# Trellis Runtime

Среда исполнения задач агентов с доменными YAML-документами. Жизненным циклом задач управляет [Tasks](../trellis-tasks/module.md).

## Вход запуска

- Назначенная Tasks работа для агента, имя которого включено в конфигурацию Runtime.
- Закреплённый пакет агента из [Registry](../trellis-registry/module.md) и домен его результата из [конфигурации](../trellis-framework/domains.yaml).
- Точная ревизия Framework и базовый снимок документов.
- Разрешённые Knowledge файловые снимки и инструменты с дополнительными ограничениями среды запуска.

## Целевое исполнение пакета

Один пакет задаёт одну ограниченную задачу. Runtime передаёт внешнему CLI/SDK-агенту `AGENTS.md`, выбранные YAML-навыки, примеры и текст целевой схемы с раскрытыми `$ref`-ссылками на её зависимости. Текст формируется из того же зафиксированного набора схем пакета, по которому [Tasks](../trellis-tasks/module.md) механически проверяет гейты. Runtime не подменяет эти схемы последней ревизией Framework; дополнительный контекст соседних доменов запрашивается по закреплённой ревизии.

`AGENTS.md` может описывать короткую процедуру в рамках задачи, включая работу в ветке предложения. Машинные условия входа, выхода и завершения задаются гейтами в YAML. Runtime передаёт Tasks результат попытки и данные для проверки гейтов; прохождение гейтов и состояние задачи определяет Tasks. Чтение соседних документов осуществляется файлами; MCP используется там, где нужна операция сервиса.

В [примере проверки комплаенса](../trellis-framework/examples/compliance-check-agent-package/module.md) Runtime передаёт агенту один продукт, выбранные ограничения, домены чтения и разрешённые пути записи. Агент возвращает ветку и commit; Runtime передаёт их Tasks для Git-гейтов.

Для [активного пакета product](../trellis-framework/domains/product/agent/module.md) Runtime передаёт запрос и пути текущих требований на закреплённом снимке; пустой список означает первую итерацию. Схема навыка раскрывает все восемь типов документов, а результат содержит ветку и commit предложения.

[Projects](../trellis-knowledge/projects/module.md) проверяет проектный доступ, а [Repositories](../trellis-knowledge/repositories/module.md) предоставляет локальные снимки точных ревизий и изолированные рабочие копии. Runtime не расширяет эти разрешения и не управляет учётными записями или жизненным циклом проектов.

## Результат

Результат автора — предложение документов и открытые вопросы. Результат AI-проверки — находки по объявленным критериям, основания и неопределённость. Проверяющий навык сам по себе не получает права применения.

Ход исполнения и вопросы человеку передаются в Tasks, итоговые артефакты и предложения — в Knowledge. Knowledge проверяет предложение; успешное исполнение Runtime и прохождение гейтов задачи не принимают документы автоматически. Клиент показывает состояние задачи и изменения, человек принимает решение по предложению. Отмена задачи останавливает выполняемую попытку, но не откатывает ранее принятое изменение.

## Работа по принятому изменению

В действующей конфигурации доменов подписки `on_change` указывают исходные домены. Целевая конфигурация связывает такую подписку с конкретным пакетом агента. Tasks обрабатывает принятое изменение и назначает Runtime проверку комплаенса при изменении продукта или комплаенса. Повтор доставки одного события не создаёт новую независимую задачу.

При изменении каталога ограничений пересматривается применимость к продуктам в выбранной базе, включая ограничения без существующих сопоставлений. Результаты проверки сами не запускают эту же проверку: домен не подписан на себя. Runtime выполняет только назначенную ему попытку и не владеет подписками или повторами задач.

## Граница реализации

[Граница компонента](module.md) определяет место исполнения. Подключение LLM, очередь событий, обработка пакетов с YAML-гейтами и работающий agent harness здесь не реализованы.
