# Trellis Runtime

Среда работы агентов с доменными YAML-документами.

## Вход запуска

- Выбранный домен из [конфигурации](../trellis-framework/domains.yaml).
- Точная ревизия Framework и базовый снимок документов.
- Задача человека либо событие принятого изменения.
- Разрешённые Knowledge файловые снимки и инструменты с дополнительными ограничениями среды запуска.

Runtime собирает инструкции агента, навык, схему целевого документа, её смысловые критерии и нужные примеры. Чтение соседних документов осуществляется файлами; MCP используется там, где нужна операция сервиса.

[Projects](../trellis-knowledge/projects/module.md) проверяет проектный доступ, а [Repositories](../trellis-knowledge/repositories/module.md) предоставляет локальные снимки точных ревизий и изолированные рабочие копии. Runtime не расширяет эти разрешения и не управляет учётными записями или жизненным циклом проектов.

## Результат

Результат автора — предложение документов и открытые вопросы. Результат AI-проверки — находки по объявленным критериям, основания и неопределённость. Проверяющий навык сам по себе не получает права применения.

Предложение передаётся в Knowledge. Клиент показывает изменения, человек принимает решение. Отмена запуска не откатывает ранее принятое изменение.

## Реакции на изменения

Подписки указаны явно в конфигурации доменов. Домен проверки комплаенса реагирует на принятые изменения продукта и комплаенса. Повтор доставки одного события не создаёт новую независимую работу.

При изменении каталога ограничений пересматривается применимость к продуктам в выбранной базе, включая ограничения без существующих сопоставлений. Результаты проверки сами не запускают эту же проверку: домен не подписан на себя.

## Граница реализации

[Граница компонента](module.md) определяет место исполнения. Подключение LLM, очередь событий и работающий agent harness здесь не реализованы.
