# Документация продукта

## Ответственность и границы

`docs/` описывает пользовательские требования и порядок развития Trellis. Документы связывают ожидаемое поведение продукта с проверяемыми результатами работ.

- `requirements/` — пользовательские истории, функциональные и нефункциональные требования.
- `plan/` — порядок реализации и приёмки пользовательских историй, зависимости и открытые решения.

Документация компонентов в `module.md` определяет архитектурные границы. Требования не заменяют контракты в коде, а дорожная карта не является свидетельством реализации. Архитектурные решения с влиянием на компоненты фиксируются рядом с соответствующей границей.
