# Этап 1 — папки Explorer

## Результат на 2026-09-15

Реализация первого этапа выполнена в ветке `feat/stage-1-workspace-folders`. По уточнению пользователя список папок сосредоточен в боковой панели, вкладка остаётся пустой до подключения Grafel, а журнал и проверка доступности доступны в заголовке панели. Сценарии VS Code прошли для сборки 0.2.1. Проверка Cursor отложена по указанию пользователя; совместимость первого этапа с Cursor пока не считается подтверждённой.

Область: US-02 и диагностика доступности папок из US-09; FR-02 и относящаяся к этому этапу часть FR-09. Это не приёмка полного MVP или всей истории US-09. Grafel, индексация, dashboard и MCP относятся к следующим этапам.

## Изменения и границы

- [WorkspaceProjects](../../plugin/src/ide/workspaceProjects.ts) читает имена, URI и порядок непосредственно из `workspaceFolders`. Общий выбор хранится только в памяти окна; удаление выбранного корня сбрасывает его.
- [WorkspaceTree](../../plugin/src/ide/workspaceTree.ts) показывает папки, выбор и состояния из контекста. Дерево показывает выбранную папку в Explorer; добавление выполняет штатная команда редактора. Своего реестра и удаления нет.
- [folderAccess](../../plugin/src/ide/folderAccess.ts) проверяет открытие локального каталога без чтения исходников. Нелокальные URI, отсутствующие папки и ошибки доступа имеют объяснение и следующее действие. Контекст ограничивает ожидание пятью секундами; повторная проверка и журнал доступны из UI.
- `resolveAnalysisProject()` проверяет доверие, доступность и неизменность исходного выбора. Это подготовка контекста будущей операции, без запуска анализа. Поздние ответы не возвращают удалённые папки и не переключают операцию на соседний проект.
- [HomePanel](../../plugin/src/ide/homePanel.ts) не зависит от контекста проектов: вкладка содержит пустой документ без действий, скриптов и ресурсов. Открытие доступно только через палитру команд. Стили прежней страницы и транспорт её command-ссылок удалены; выбор по URI работает через дерево и палитру.

Изменения остаются в `plugin/src/ide` и точке композиции; ресурсы и проверки размещены в существующих `plugin/media` и `plugin/test`. Границы описаны в [module.md](../../plugin/src/ide/module.md). Submodule Grafel не изменён.

## Выполненные сценарии VS Code

Проверки выполнялись в настоящем Extension Host и Chromium редактора. Компоненты тестов загружены из `artifacts/stage-1-0.2.1/vsix/extension/dist`, а не из копии исходников в тестовой сборке.

| Сценарий | Ожидаемое и фактическое поведение |
|---|---|
| Открытие одной папки | Окно без `.code-workspace` показывает единственный корень редактора. Пройдено. |
| Активация и жизненный цикл вкладки | Автоматического открытия нет; повторная команда использует одну пустую вкладку; закрытие и повторное открытие работают. Открытие убрано из дерева и заголовка панели. Пройдено. |
| Добавление и отмена | Действие в боковой панели открывает штатный диалог; Escape сохраняет список. Повторное действие добавляет вторую папку. Пройдено. |
| Одноимённые папки | Два корня `Проект & docs %20 #plus+` имеют разные пути и URI. Explorer и боковая панель согласованы. Вложенная папка не становится проектом. Пройдено. |
| Выбор и переход | Команда выбирает второй URI; палитра и QuickPick с клавиатуры выбирают первый; щелчок в дереве выбирает второй и показывает соответствующий корень в Explorer. Пройдено. |
| Изменение состава | Удаление выбранного корня средствами API редактора обновляет панель, сбрасывает выбор и запрещает устаревший URI. Своей команды удаления нет. Пройдено. |
| Диагностика и восстановление | Отсутствующий каталог, файл вместо каталога и нелокальный URI дают различимые причины. После создания отсутствовавшей папки команда проверки в заголовке панели восстанавливает доступность. Пройдено. |
| Журнал | Кнопка в заголовке панели открывает Output с журналом Trellis; подтверждена запись `ENOENT` для отсутствующей папки. Пройдено. |
| Асинхронные отказы | Задержанные ответы не меняют новый контекст; смена выбора во время подготовки даёт отказ. Зависшая и отклонённая проверки имеют конечную безопасную диагностику. Пройдено с управляемым probe. |
| Пустой workspace и сохранность | Список пуст, действие добавления доступно; контрольный файл в папке проекта сохраняет содержимое после изменений workspace. Пройдено. |
| Перезапуск | Отдельный запуск того же сохранённого workspace восстанавливает два корня из API; старый выбор не сохраняется. Пройдено. |
| Недоверенный workspace | `workspace.isTrusted === false`: оболочка открывается, подготовка анализа запрещена. Пройдено. |
| Отображение | Проверены светлая и тёмная темы, длинные пути, текст состояния и выбор с клавиатуры. Вкладка остаётся пустой и не содержит действий при изменении workspace, выборе, диагностике и перезапуске. Пройдено. |

Для UI-автоматизации только в тестовом профиле включён штатный упрощённый диалог `files.simpleDialog.enable`. Системный Windows-диалог отдельно не автоматизировался. Для проверки доверия используется прямой запуск хоста, поскольку `test-electron` добавляет `--disable-workspace-trust`.

## Оставшиеся проверки

- Cursor: отложено пользователем; успешное открытие одной папки в промежуточном запуске не считается приёмкой редактора.
- Ошибки ACL `EACCES/EPERM` имеют обработку, но отдельный сценарий изменения Windows ACL не выполнялся. Тайм-аут проверен управляемой задержкой, а не отключением реального сетевого диска.
- Полная диагностика движка/индекса, поддержка языков, производительность анализа и сквозная приёмка одного VSIX с Grafel относятся к последующим этапам Roadmap.
