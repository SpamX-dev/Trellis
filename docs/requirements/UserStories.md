# Пользовательские истории MVP Trellis

## Цель и границы

Разработчик устанавливает Trellis, открывает или добавляет папку в workspace редактора, индексирует её и использует структуру кода через dashboard и AI-агента в Cursor. Работа с проектами, индексацией и dashboard проверяется также в VS Code на Windows x64. Обязательный MCP-клиент первой приёмки — Cursor.

Это целевой план MVP, а не описание текущей версии 0.1.0. Правила операций определены в [Functional.md](Functional.md), ограничения — в [NonFunctional.md](NonFunctional.md), последовательность и открытые решения — в [Roadmap.md](../plan/Roadmap.md).

**Принятое решение D-01:** Trellis показывает корневые папки текущего workspace — те же, что в Explorer редактора. Собственного набора отслеживаемых папок нет. Добавление выполняется штатной командой редактора; отдельное удаление в Trellis не реализуется. В MVP входят восемь историй; идентификатор исключённой US-03 сохранён, чтобы не перенумеровывать остальные.

## US-01 — Установить готовый продукт

Как разработчик, я хочу установить один VSIX, чтобы начать работу без ручной установки Grafel и инструментов сборки.

Критерии приёмки:

- VSIX устанавливается в VS Code и Cursor на Windows x64 без прав администратора.
- При открытии Trellis доступна боковая панель. Вкладка зарезервирована под Grafel: до его подключения она пуста и открывается командой из палитры.
- Совместимый движок и dashboard поставляются внутри VSIX; для их подготовки не нужны отдельные загрузки, Node.js, Go или Git на машине пользователя.
- Повторная установка той же версии не меняет состав workspace и не сбрасывает настройки Trellis.
- Ошибка подготовки компонента отображается с понятным действием восстановления.

Связанные требования: FR-01, FR-04; NFR-01, NFR-02, NFR-04.

## US-02 — Работать с папками Explorer

Как разработчик, я хочу видеть в Trellis папки текущего workspace, чтобы анализировать проекты, с которыми работаю в Explorer редактора.

Критерии приёмки:

- Боковая панель показывает все корневые папки текущего workspace с именем, полным путём и состоянием. Вкладка не дублирует список. Отдельно регистрировать папку в Trellis не нужно.
- Действие «Добавить папку» вызывает штатное добавление в workspace. Добавленная папка появляется и в Explorer, и в Trellis; отмена выбора ничего не меняет.
- Состав списка обновляется при изменениях workspace средствами редактора. Вложенные каталоги не становятся отдельными проектами автоматически.
- Разные папки с одинаковым именем различимы по пути; Trellis не создаёт дополнительные записи поверх списка редактора.
- После открытия сохранённого workspace Trellis показывает его текущие папки. Хранением и восстановлением состава workspace управляет редактор.
- Если папка workspace недоступна или её URI не поддерживается для анализа, Trellis показывает причину и не запускает анализ для неё.
- В пустом workspace показано действие добавления папки. Добавление не запускает индексацию автоматически.
- Команд удаления папки или отдельного прекращения отслеживания в Trellis нет. Штатные возможности Explorer не изменяются.

Связанные требования: FR-02, FR-09; NFR-03, NFR-04, NFR-07.

## US-03 — Удаление из отслеживания: исключено

По решению пользователя отдельное удаление в Trellis не реализуется. История не входит в этапы или критерии готовности MVP; FR-03 также исключено. Актуализация представлений при штатном изменении workspace относится к US-02.

## US-04 — Получить готовый к работе движок

Как разработчик, я хочу, чтобы Trellis сам управлял движком, чтобы мне не приходилось запускать сервисы и разбираться с портами.

Критерии приёмки:

- Движок запускается при первой операции, которой он нужен; пользователь видит состояние запуска.
- Готовность подтверждается ответом совместимого движка, а не только наличием процесса.
- Повторная операция не создаёт лишний процесс; несколько окон редактора не повреждают общие данные.
- Сбой, несовместимость и занятый адрес не приводят к подключению к случайному экземпляру Grafel.
- После ошибки доступен повторный запуск; при закрытии последнего владельца освобождаются ресурсы Trellis.

Связанные требования: FR-04, FR-09; NFR-02, NFR-04, NFR-05.

## US-05 — Выполнить первый анализ проекта

Как разработчик, я хочу запустить индексацию выбранного проекта и увидеть её результат, чтобы понимать, какие данные доступны для работы.

Критерии приёмки:

- Команда запуска явно относится к выбранному отслеживаемому проекту.
- Во время работы видно состояние «Индексируется»; повторный запуск для этого проекта не создаёт второй анализ.
- Успех показывает состояние «Готов», время последнего успешного анализа и доступную сводку результата.
- Ошибка показывает причину и возможность повторить операцию; «Готов» не отображается при неуспехе.
- Отсутствие поддерживаемого кода обозначается явно и не выдаётся за содержательный граф.
- На контрольном проекте, созданном перед проверкой индексации, проверены ожидаемые определения и связи, а не только факт создания файла индекса.

Связанные требования: FR-05, FR-09; NFR-03, NFR-05, NFR-06, NFR-08.

## US-06 — Обновить анализ после изменения кода

Как разработчик, я хочу вручную переиндексировать проект, чтобы граф и ответы агента учитывали новые исходники.

Критерии приёмки:

- Для ранее проиндексированного проекта доступна повторная индексация.
- После успешного обновления добавленная связь появляется, а удалённая исчезает в dashboard и MCP.
- Время успешного анализа изменяется только при успехе; ошибочная попытка не подменяет его.
- При ошибке предыдущий успешный результат сохраняется и явно обозначается как результат предыдущего анализа.
- После перезапуска Trellis доступность сохранённого результата проверяется повторно.

Связанные требования: FR-05, FR-06, FR-09; NFR-04, NFR-06, NFR-08.

## US-07 — Исследовать структуру проекта

Как разработчик, я хочу открыть граф выбранного проекта, найти сущность и увидеть её связи, чтобы ориентироваться в коде.

Критерии приёмки:

- Trellis открывает dashboard Grafel с понятным контекстом выбранного проекта.
- В dashboard можно найти сущность и рассмотреть её связи и доступное местоположение в исходниках.
- Проект без индекса предлагает сначала выполнить анализ; недоступный движок показывает ошибку подключения.
- Повторное открытие не создаёт дополнительный движок.
- Данные другого проекта не выдаются за данные выбранного. Способ открытия dashboard согласуется в D-02.

Связанные требования: FR-07, FR-09; NFR-03, NFR-05, NFR-07, NFR-08.

## US-08 — Использовать структуру кода через агента

Как разработчик, я хочу подключить Trellis к агенту Cursor, чтобы получать ответы о связях в проиндексированном проекте.

Критерии приёмки:

- По явному действию пользователя Trellis настраивает собственное подключение MCP, сохраняя остальные настройки клиента.
- Повторное подключение не создаёт дублирующие записи; собственное подключение можно отключить.
- Агент в реальном Cursor обнаруживает инструменты и выполняет запрос к выбранному проекту.
- Для контрольного вопроса «Кто вызывает этот метод?» ответ содержит проверяемые сущности и местоположения в коде.
- Недоступный или неиндексированный проект даёт понятный ответ об отсутствии данных, без переключения на чужой проект.
- После переиндексации повторный запрос отражает изменение кода.

Связанные требования: FR-08, FR-09; NFR-03, NFR-04, NFR-08.

## US-09 — Понять и устранить проблему

Как разработчик, я хочу видеть состояние Trellis и открыть журнал конкретной операции, чтобы восстановить работу после ошибки.

Критерии приёмки:

- Различимы состояние движка, состояние индекса проекта и доступность его папки.
- Ошибка содержит операцию, проект, краткое объяснение и доступное следующее действие.
- Можно открыть журнал, повторить неудачную операцию и увидеть успешное восстановление.
- Проверка доступности папок и открытие журнала доступны командами в заголовке боковой панели, без открытия вкладки.
- Повторная ошибка не вызывает поток одинаковых уведомлений.
- В журнале есть версии компонентов и техническая причина, но нет секретов и полных исходников по умолчанию.

Связанные требования: FR-09; NFR-03, NFR-04, NFR-07.

## За пределами MVP

Собственный реестр папок и отдельная команда удаления в Trellis исключены принятой моделью Explorer. За пределами MVP также остаются автоматическая индексация при изменении файлов, отдельная кнопка отмены анализа, собственный граф или чат Trellis, генерация документации, аудиты, сравнение Git-ревизий, облако, совместная работа, поддержка всех MCP-клиентов, WSL/SSH/контейнеры и универсальная гарантия качества для всех языков. Отдельная очистка кэша и межпроектный анализ отложены. Штатное безопасное завершение процессов остаётся требованием MVP.
