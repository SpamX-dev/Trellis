# Функциональные требования MVP Trellis

## Назначение и модель

Требования уточняют [пользовательские истории](UserStories.md). Каждый FR должен проверяться вместе с указанными историями и [нефункциональными ограничениями](NonFunctional.md).

- **Проект** — корневая папка текущего workspace, отображаемая в Explorer редактора. Git-репозиторий не обязателен; анализ в MVP поддерживает локальные папки.
- **Контекст Trellis** — текущий workspace редактора и выбранный среди его папок проект. Состав и восстановление workspace определяет редактор, а Trellis получает папки через его API.
- **Отслеживание** — отображение текущих папок workspace в Trellis. Отдельной регистрации и собственного списка нет; это не означает наблюдение за файлами или автоматический анализ.
- **Индекс** — результат успешного анализа конкретного проекта согласованной версией движка.

Модель связи с Explorer подтверждена пользователем в D-01 [дорожной карты](../plan/Roadmap.md). FR-03 исключено: отдельная операция удаления в Trellis не разрабатывается.

## FR-01 — Установка и оболочка

История: US-01.

1. Поставка содержит один VSIX с расширением, совместимым исполняемым файлом Grafel для Windows x64 и dashboard.
2. Trellis предоставляет боковую панель со списком проектов и вкладку, зарезервированную под Grafel. До подключения Grafel вкладка пуста и открывается только командой из палитры. Повторная команда открытия активирует одну вкладку Trellis в окне.
3. Установка и запуск не требуют глобальной установки Grafel или средств сборки. Расширение сообщает об отсутствии или повреждении своего компонента.
4. Обновление расширения сохраняет настройки Trellis и не меняет состав workspace; несовместимый сохранённый индекс требует повторного анализа, а не молчаливого использования.

## FR-02 — Папки workspace и связь с Explorer

История: US-02. Основание: принятое решение D-01.

1. Единственный источник состава проектов — `vscode.workspace.workspaceFolders`. Trellis показывает те же корневые папки, что Explorer редактора, сохраняя имена, URI и порядок из API. Отдельный сохраняемый реестр не создаётся.
2. Действие «Добавить папку» вызывает штатную команду `workbench.action.addRootFolder`. Оно добавляет папку в workspace, после чего её отображают Explorer и Trellis. Отмена не меняет состояние.
3. Список папок отображается только в боковой панели и обновляется при изменениях состава workspace. Вкладка не дублирует список. При перезапуске или смене workspace список снова читается из API редактора; хранить независимую копию списка не нужно.
4. Для обращения к проекту используется URI папки workspace, а не имя или индекс строки. Одноимённые папки различаются по полному пути. Управление составом и идентичностью папок workspace остаётся у редактора.
5. Недоступная папка, остающаяся в workspace, отображается с объяснением. Нелокальные URI можно отображать, но их анализ в MVP недоступен с понятной причиной.
6. В пустом workspace показывается предложение добавить папку. Новая папка автоматически появляется в Trellis, но её индексация запускается только явно.
7. Активный проект должен принадлежать текущему workspace. Если его больше нет в workspace, выбор сбрасывается и новые операции для него недоступны; другой проект не подставляется в уже начатую операцию. Dashboard и MCP используют этот же контекст.
8. Выбор папки в боковой панели Trellis показывает её в Explorer. Команд удаления папки, исключения из отслеживания и самостоятельного управления составом проектов в Trellis нет; штатные действия редактора сохраняются.

## FR-03 — Удаление из отслеживания: исключено

Требование исключено вместе с US-03 по решению пользователя. Идентификатор сохранён для стабильности ссылок; работ и критериев приёмки по нему нет. Обновление контекста при изменениях workspace определено в FR-02.

## FR-04 — Подготовка и жизненный цикл движка

Истории: US-01, US-04.

1. Перед операцией расширение определяет свою версию движка, подготавливает рабочие данные и запускает процесс при необходимости.
2. Подключение проверяет готовность, совместимость и принадлежность экземпляра Trellis. Чужой сервис на нужном адресе не считается исправным движком.
3. Состояния движка: «Остановлен», «Запускается», «Готов», «Ошибка». Запуск ограничен конечным тайм-аутом, заданным в реализации и проверенном сценарии отказа.
4. Повторные запросы запуска объединяются. Правила владения процессом и данными при нескольких окнах фиксируются перед реализацией в D-04.
5. При завершении владельца его операции завершаются безопасно. Общий процесс, если выбран такой вариант, останавливается только после освобождения последнего владельца.
6. После сбоя повторная операция может заново запустить движок. Непрерывные автоматические перезапуски без ограничения запрещены.

## FR-05 — Индексация

История: US-05.

1. Запуск допускается для доступного отслеживаемого проекта в доверенном контексте редактора.
2. В MVP выполняется не более одной операции индексации на экземпляр движка. При занятом движке новая команда получает понятный ответ; скрытой очереди нет.
3. На время операции проект получает состояние «Индексируется». Процент показывается только при наличии достоверных данных движка; иначе достаточно этапа или неопределённого индикатора.
4. Успех фиксируется после завершения анализа и проверки доступности результата через интерфейс Grafel. Код завершения процесса или наличие файла сами по себе недостаточны.
5. Успешный результат содержит идентичность проекта, время анализа и версию движка. Доступная статистика показывается без выдуманных значений.
6. Ошибки доступа, неподдерживаемый код, аварийное завершение и отсутствие результата различаются в сообщении пользователю. Анализ не изменяет исходники.

## FR-06 — Повторный анализ и сохранённый результат

История: US-06.

1. Повторная индексация запускается вручную по тем же правилам, что первый анализ. Изменения файлов сами по себе её не запускают.
2. Новый успешный результат становится доступен dashboard и MCP согласованно. Неудачная попытка не уничтожает предыдущий успешный результат.
3. Пока новое построение не завершено, разрешается использовать предыдущий результат только с указанием его времени. При отсутствии результата запрос сообщает, что данные ещё не готовы.
4. После ошибки состояние проекта — «Ошибка»; наличие предыдущего индекса и время его создания показываются отдельно.
5. После перезапуска проверяются существование и совместимость сохранённого результата. Trellis не обещает актуальность относительно текущих файлов без повторного анализа и всегда показывает время последнего успеха.

## FR-07 — Dashboard

История: US-07. Зависимость: D-02.

1. Команда открывает существующий dashboard Grafel для явно выбранного проекта. Способ открытия — Webview или системный браузер — определяется отдельным решением; реализация собственного графа не входит в MVP.
2. Пользователю доступны поиск сущности, просмотр её связей и доступных местоположений в исходниках. Нужные возможности проверяются на закреплённой ревизии Grafel.
3. До открытия проверяются принадлежность проекта текущему контексту, наличие индекса и доступность движка.
4. При потере доступа отображается понятная ошибка; проект нельзя незаметно заменить другим.
5. Trellis и dashboard используют папки текущего workspace как единый набор проектов; независимое управление списком в dashboard не должно создавать второй набор папок.

## FR-08 — MCP в Cursor

История: US-08.

1. Расширение предоставляет явные действия подключения и отключения собственного MCP-сервера в Cursor. Способ и область настройки проверяются на целевой версии клиента; остальные подключения и настройки сохраняются.
2. Повторное подключение обновляет собственную запись без дублей. Отключение удаляет только запись Trellis; пользовательские изменения при конфликте не перезаписываются молча.
3. Каждый запрос разрешается в явно определённый отслеживаемый проект. Параллельная работа окон или смена выбора не должна менять адресата уже начатого запроса.
4. После подключения проверяются обнаружение инструментов и реальный вызов из агента Cursor. Проверка HTTP-порта или конфигурационного файла не заменяет эту проверку.
5. Ответы содержат идентичность проекта и данные, позволяющие проверить сущности и связи по исходникам. Ответ от предыдущего индекса содержит доступное указание его времени.
6. Отсутствие проекта, индекса, совместимости или соединения возвращается как понятная ошибка. Trellis не переключается автоматически на отдельно установленный Grafel.
7. MCP в других клиентах и VS Code Copilot не является условием приёмки этого MVP.

## FR-09 — Состояния, ошибки и восстановление

Истории: US-02, US-04–US-09.

1. Индекс проекта имеет состояния «Не проиндексирован», «Индексируется», «Готов», «Ошибка». Доступность папки и состояние движка показываются отдельно и могут ограничивать операции при сохранённом индексе.
2. Наличие предыдущего результата и время последнего успеха хранятся отдельно от состояния последней попытки. После прерванной операции перезапуск не оставляет вечное «Индексируется».
3. Значение «Готов» означает доступный успешный индекс, а не гарантию соответствия последним изменениям файлов.
4. Ошибка содержит операцию, проект, краткую причину и следующее действие: повторить, восстановить доступ, переиндексировать или открыть журнал.
5. Журнал позволяет сопоставить операцию с проектом, версиями компонентов, началом, окончанием и причиной отказа. Повторные одинаковые ошибки не создают поток уведомлений.
6. Представления обновляются после успешного изменения данных; ошибки сохранения не маскируются визуальным успехом.
7. Команды «Проверить доступность папок» и «Открыть журнал» доступны в заголовке боковой панели; для их выполнения не нужно открывать вкладку.
